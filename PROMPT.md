## CRITICAL BUILD REQUIREMENT

**NEVER BUILD LOCALLY.**

All Android builds, Gradle tasks, APK generation, testing and release packaging MUST run through GitHub Actions workflows.

- Do not install Android Studio locally.
- Do not install or run a local Android SDK.
- Do not run Gradle build commands locally.
- Use GitHub-hosted Ubuntu runners.
- Use GitHub Actions to build, test and package the APK.
- Commit all required source files and workflow configurations to GitHub.

### GitHub Actions

Create `.github/workflows/android-build.yml`.

The workflow must:

- Trigger on pushes to `main`.
- Trigger on pull requests.
- Support manual execution using `workflow_dispatch`.
- Use a GitHub-hosted Ubuntu runner.
- Set up the required JDK.
- Set up Gradle using the official Gradle setup action.
- Build a debug APK using Gradle.
- Run available unit tests.
- Verify that the APK exists.
- Upload the APK using `actions/upload-artifact`.
- Give the artifact a clear name: `JNet-System-Monitor-APK`.

Create a separate release workflow or extend the build workflow to support tagged releases.

When a version tag such as `v1.0.0` is pushed:

- Build the release APK on GitHub Actions.
- Package the APK.
- Publish it as a GitHub Release asset.
- Do not expose signing keys or secrets.
- If release signing is not configured, clearly identify the APK as unsigned or debug-signed.
